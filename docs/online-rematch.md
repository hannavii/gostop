# 같은 방 재대결

온라인 2인 맞고와 3인 고스톱은 종료/정산 화면에서 다시하기와 동의 취소를 지원합니다. 대기실의 `ready`와 별도로 Member의 `rematchReady`를 서버가 보관합니다.

## 이벤트와 공개 상태

- 클라이언트 → 서버: `game:rematch({ roomCode, round, ready }, ack)`. 좌석은 현재 Socket.IO 멤버십에서 확인하며, 종료 전·잘못된 방·이전 판·추가 필드 요청을 거부합니다.
- 서버 → 클라이언트: 기존 `room:state`에 `round`와 `connections[].rematchReady`를 포함합니다. 대기실은 round 0, 첫 판은 1이며 새 판마다 증가합니다.
- 같은 판에서 동일한 동의 요청을 반복해도 boolean 상태 하나만 유지합니다. 새 판 시작 후 이전 판 요청은 거부하며 Match를 추가 생성하지 않습니다.

## 새 판 시작

정원의 모든 Member가 동의하고 접속했을 때 서버가 기존 `createMatch(mode)`를 재사용합니다. 선은 첫 판과 동일한 좌석 0입니다. 게임 카드·점수·카운터·뻑·선택 대기·결과는 새 Match에서 생성하고, Room/Member/좌석/닉네임/방장/토큰/소켓은 유지합니다. 동의 상태는 새 판 시작 시 false로 정리합니다.

게임 `revision`은 이전 판 최종 revision + 1부터 시작합니다. 방 안에서 계속 증가하므로 이전 판의 지연된 `game:action`도 새 판에 적용되지 않습니다. 클라이언트는 round와 revision이 지난 스냅샷을 무시하고, 보드 key에 round를 포함해 이전 presentation 타이머·스냅샷·모달을 정리합니다. 규칙이나 정산은 클라이언트에서 계산하지 않습니다.

## 재접속과 이탈

동의 상태는 Member에 남으므로 F5/재접속 후 복구됩니다. 전원이 동의해도 접속하지 않은 Member가 있으면 대기하며, 마지막 접속 복구 시 조건을 다시 검사합니다. 기존 60초 grace와 종료된 Match를 포함한 게임 방의 정책을 유지합니다. 명시적 이탈 또는 grace 만료 시 방 전체를 닫습니다. 서버 재시작 시 메모리 방이 사라지는 기존 제한도 동일합니다.

## 검증

`npm run test:online`은 2인/3인 동의·취소·초기화·중복/이전 판 요청·개인 손패·재접속·이탈을 검사합니다. `npm run test:browser-rematch`는 Edge 독립 컨텍스트에서 실제 판 종료 → 동의/취소 → 대기 중 F5 → 같은 방 새 판 → 실제 카드 제출을 360px와 데스크톱에서 검증합니다. `npm run test:browser-mobile`은 기존 네 가지 모바일 폭과 데스크톱 레이아웃, 재대결 버튼 터치를 검사합니다.

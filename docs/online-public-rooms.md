# 온라인 공개방과 빠른 참가

방 공개 설정의 기본값은 **비공개**다. 기존 `room:create`와 `room:create-mode` 요청도 계속 비공개 방을 만든다. 비공개 방은 기존 방 코드와 초대 URL로 참가한다. 생성 후 공개 여부를 변경하는 기능은 없다.

새 클라이언트는 `room:create-options`에 `{ mode, nickname, visibility }`를 보낸다. visibility는 `private` 또는 `public`만 허용한다. 서버는 Issue #16 검증 계층으로 객체 필드와 각 값을 검사하며, 잘못된 요청은 방을 생성하지 않는다.

공개 목록은 다음 조건을 모두 만족하는 방만 포함한다.

- 공개로 생성한 방
- 아직 Match가 없는 대기실
- 실제 멤버 수가 정원보다 적고 1명 이상인 방
- grace 만료 처리를 기다리는 멤버가 없는 유효한 방

목록은 서버의 생성 sequence가 큰 순서, 즉 최신순이다. 공개 summary에는 `roomCode`, `mode`, `playerCount`, `maxPlayers` 네 필드만 들어간다. 닉네임, 비공개 방 정보, token/hash, socket ID, 준비 상태, 게임 상태와 내부 timer는 포함하지 않는다.

클라이언트는 시작 화면 진입 시와 수동 새로고침 시 `room:list`를 요청한다. 서버는 같은 이름의 이벤트로 summary 배열을 보내고 기존 ACK 형태로 성공/실패를 응답한다. 요청 payload는 없으며 추가 인자는 거부한다. 목록 조회는 멤버·게임·로그를 변경하지 않는다.

목록을 조회한 미참가 socket만 갱신 알림을 구독한다. 공개 목록이 실제로 바뀌는 생성·참가·퇴장·grace 만료·시작·삭제 시 `room:list-changed`를 보낸다. 비공개 방의 변경이나 준비 상태·턴·타이머 tick에는 알리지 않는다. 참가·복구·disconnect 시 구독을 제거한다. UI는 겹치는 요청을 합치고 처리 중 추가 변경이 오면 한 번 더 조회한다. 주기적인 polling이나 방송은 없다.

재접속 grace 중인 멤버도 `playerCount`에 포함한다. disconnect를 빈 좌석으로 취급하지 않으며, 실제 만료 후 기존 lobby 정책으로 멤버 제거·방장 승계·빈 방 삭제를 처리한다. 만료 정리 전인 방은 목록에서 제외한다.

빠른 참가는 입력한 닉네임과 목록의 방 코드를 기존 `room:join`으로 보낸다. 서버가 실제 정원·Match 존재·기존 소속·닉네임·방 코드를 다시 검사한다. 오래된 목록에서 동시에 마지막 좌석을 선택해도 한 요청만 성공하며 나머지는 기존 오류를 받고 목록을 갱신한다.

화면의 우선순위는 재접속 session 복구 → 초대 URL 참가 → 일반 시작 화면의 공개 목록이다. 초대 화면에서 공개 목록을 자동 조회하거나 다른 방에 자동 참가하지 않는다. 복구 가능한 session이 있으면 공개 목록을 표시하지 않는다. 정상 참가 후 초대 상태를 해제하므로 이후 방을 나가면 공개 목록을 볼 수 있다.

목록의 로딩·오류·빈 상태를 구분하며, 목록 오류는 방 만들기나 코드 참가를 막지 않는다. 목록은 모바일에서도 줄바꿈 가능한 카드형으로 표시한다.

검증 명령:

- `npm run test:validation`: 기존 입력 검증 + 공개방 보안/lifecycle/동시 참가 통합 테스트
- `npm run test:online`: 위 서버 테스트를 포함한 온라인 전체 테스트
- `npm run test:e2e`: 기존 시나리오와 공개방 브라우저 테스트 전체

방과 목록은 기존처럼 서버 프로세스 메모리에 있다. 서버 재시작 시 사라지며, 다중 서버 간 동기화나 전체 rate limiter는 추가하지 않았다.

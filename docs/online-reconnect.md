# 온라인 재접속 / 새로고침 복구

2인 맞고와 3인 고스톱 모두 서버 프로세스가 살아 있는 동안 같은 좌석으로 복구할 수 있다. DB, Redis, 계정은 사용하지 않는다. `server/game.ts`의 Match, 규칙 엔진과 정산 로직은 변경하지 않았다.

## 상태와 토큰

기존 Room의 소켓 ID 배열을 고정 좌석의 Member 배열로 변경했다. 배열 인덱스가 좌석이며, disconnect가 발생해도 삭제하거나 재정렬하지 않는다.

| Member 필드 | 용도 |
| --- | --- |
| socketId | 현재 권한을 가진 소켓 ID, 연결이 끊기면 null |
| tokenHash | 32바이트 무작위 토큰의 SHA-256 해시 |
| deadline | 재접속 만료 시각(Unix epoch ms), 연결 중에는 null |
| timer | 해당 좌석의 만료 타이머 |

생성/참가 성공 시 서버는 `randomBytes(32)`로 토큰을 생성하고 **해당 소켓에만** `room:session`을 보낸다. 공개 상태에는 토큰/해시/소켓 ID를 넣지 않는다. 클라이언트는 `sessionStorage['gostop.online.reconnect']`에 `{ roomCode, token }`만 저장하며, 손패나 전체 Match를 저장하지 않는다.

토큰은 해당 방의 해당 Member 안에서 검증한다. 요청에 좌석을 지정할 수 없고, 다른 방에서 같은 토큰을 사용하거나 이미 다른 좌석을 점유한 소켓이 좌석을 바꾸려 하면 거부한다. 토큰 소유가 복구 권한이므로 토큰을 복사한 다른 연결은 원래 좌석을 복구할 수 있다. 계정 기반 본인 확인은 이번 범위가 아니다.

## 복구 흐름과 이벤트

| 방향 | 이벤트 | 내용 |
| --- | --- | --- |
| 서버 → 본인 | `room:session` | `{ roomCode, token }` 발급/복구 확인 |
| 클라이언트 → 서버 | `room:resume(session, ack)` | 방 코드·토큰으로 기존 좌석 복구 |
| 서버 → 연결된 각 좌석 | 기존 `room:state` | 자신의 GameView와 공개 연결 상태 |
| 서버 → 연결된 참가자 | 기존 `room:closed` | 명시적 퇴장·유예 만료·이전 연결 권한 해제 |

`RoomView.connections`는 `{ seat, connected, reconnectDeadline }[]`이다. occupancy는 연결된 소켓 수가 아니라 예약된 좌석 수를 뜻한다. 복구를 기다리는 자리는 신규 참가자에게 제공하지 않는다.

1. 새로고침 시 App은 유효한 저장 세션이 있으면 온라인 화면으로 진입한다.
2. Socket.IO가 연결될 때마다 저장된 방 코드/토큰으로 `room:resume`을 보낸다. 연결/복구 중에는 게임 입력을 막는다.
3. 서버는 방의 만료 여부와 토큰을 확인하고 같은 Member에 새 소켓을 연결한다. 이전 만료 타이머를 취소한다.
4. F5 시 이전 소켓의 끊김 감지가 늦어도 복구할 수 있다. 이전 소켓의 멤버십을 먼저 제거하고 연결을 닫아 새 연결 하나만 행동 권한을 가진다. 이전 소켓의 뒤늦은 disconnect는 새 좌석에 영향을 주지 않는다.
5. 기존 `gameView(match, seat)`로 최신 전체 상태를 다시 전송한다. Match/revision은 복구 자체로 변경하지 않는다.

자기 손패, 다른 손패 장수, 바닥패·획득패, 더미 장수, 턴, GO/STOP, 뻑 소유자, 폭탄/흔들기 기록, 패스 수, 정산 결과를 동일하게 복구한다. 손패/더미의 바닥 선택 대기 상태와 특수 행동 후보는 원래 행동자에게만 보낸다. 로컬에서 열었던 폭탄/흔들기 확인창은 재구성하지 않지만 서버 후보가 복구되므로 해당 손패를 다시 눌러 선택할 수 있다.

토큰은 복구할 때 회전시키지 않는다. 응답을 놓쳐도 같은 요청을 다시 보내 안전하게 같은 좌석에 연결할 수 있다. 복구 요청은 acknowledgement 시간 초과 시 1초 뒤 다시 시도하며, 서버가 명시적으로 거부하면 저장 세션을 지우고 로비에서 이유를 표시한다. 게임 행동은 자동 재전송하지 않는다.

## 유예와 종료 정책

- `server/app.ts`의 **`RECONNECT_GRACE_MS = 60_000`**: 서버가 disconnect를 감지한 시점부터 60초간 좌석을 보존한다. 실제 네트워크 단절을 감지하기까지 Socket.IO의 heartbeat 시간이 추가될 수 있다.
- 끊긴 플레이어의 차례는 그대로 기다린다. 자동 턴 넘기기나 AI 대행은 없다. 다른 연결된 플레이어의 정당한 차례는 진행할 수 있다.
- 어느 좌석이든 기한이 만료되면 **방 전체를 종료**한다. 남은 플레이어에게 종료 이유를 알리고 Match와 모든 토큰을 무효화한다. 접속자가 아무도 없는 방도 같은 방식으로 정리한다.
- 타이머 실행이 늦어질 수 있으므로 참가/복구/동기화/행동 시에도 만료 시각을 검증한다. 성공한 복구 후 다시 끊기면 새 60초 유예가 시작된다.
- `room:leave`는 유예 없이 즉시 방을 종료한다. 연결된 클라이언트는 저장 토큰을 지운다. 오프라인 참가자는 나중에 복구 거부를 받으면 저장 토큰을 지운다.
- 서버 프로세스 종료/재시작 시 상태가 사라진다. 다른 서버 프로세스는 이전 토큰을 복구할 수 없다.
- sessionStorage는 같은 탭의 새로고침에 유지된다. 탭을 닫거나 저장소를 비우면 자동 복구할 수 없다. 저장소 사용이 차단된 경우 안내를 표시하고, 실행 중인 페이지에서는 메모리의 토큰으로 일시적 네트워크 재연결만 지원한다.

## 검증

```sh
npm run test:online
node --test tests/pansseul.test.mjs
npm run typecheck
npm run build
```

`server/tests/reconnect.test.ts`는 실제 Socket.IO 소켓으로 두 모드의 모든 좌석 복구·손패 비공개·토큰 거부·다른 방/좌석 재사용 거부·연결 교체·기한 만료·대기방·손패/더미 선택·GO/STOP·폭탄 상태·완료 정산 복구를 검사한다. 짧은 만료 시간과 결정적인 Match는 서버 생성자의 내부 테스트 옵션으로 주입하며 클라이언트가 설정할 수 없다. 기존 즉시 disconnect 종료 테스트는 명시적 `room:leave` 종료 검사로 변경했다. `tests/reconnect-session.test.ts`는 저장/삭제·잘못된 저장 데이터·저장소 차단을 검사한다.

실제 브라우저 검증은 재실행 가능한 `tests/browser-reconnect.mjs`에 두었다:

```sh
npm run test:browser-reconnect
```

기본값은 Windows에 설치된 Edge다. 다른 Chromium 실행 파일을 쓰려면 `BROWSER_EXECUTABLE` 환경 변수를 지정한다. headless 독립 브라우저 컨텍스트 2개/3개에서 게임 중 모든 좌석 F5 → 같은 좌석과 상태 복구 → 전체 transport 연결 끊기/자동 복구 → 게임 계속 진행 → 명시적 퇴장/저장 토큰 삭제를 검사한다. 브라우저 개발자 프로토콜을 사용하므로 추가 의존성은 필요 없다. 임시 프로필은 Git에서 무시되는 `.tmp-online.local/` 아래 생성하고 종료 시 해당 프로필만 삭제한다.

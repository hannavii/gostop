# 온라인 방 초대 링크

초대 URL은 `현재 origin + 현재 pathname + ?room=ABC123` 형식이다.
운영 도메인을 하드코딩하지 않으며 localhost와 배포 주소에서 동일하게 동작한다.
기존 query와 hash, URL 자격증명은 복사하지 않는다. 초대 링크에는 공개 방 코드만 담고
reconnect token, socket ID, 좌석, 손패 또는 내부 상태를 넣지 않는다.

## 참가 흐름

1. 대기실의 방 코드 옆 **초대 링크 복사**를 누른다. 기존 방 코드 복사도 유지한다.
2. 링크를 연 새 사용자는 바로 온라인 화면에 진입하고 방 코드가 채워진다.
3. 닉네임을 입력하고 **참가하기**를 누르면 기존 `room:join` 요청을 전송한다.
4. 서버가 방 존재 여부·정원·게임 상태와 닉네임을 검증한 뒤 같은 대기실에 입장시킨다.

닉네임은 기존대로 저장하지 않는다. URL만으로 임의 닉네임이나 자동 참가를 생성하지 않는다.
링크에서 게임 모드를 추측하지 않으며 참가한 방의 서버 상태를 사용한다.

## 파싱과 오류

작은 `src/online/inviteUrl.ts` 유틸리티에서 URLSearchParams로 room을 읽는다.
공백을 정리하고 기존 6자리 ASCII 영문·숫자 형식을 검증한 뒤 대문자로 통일한다.
빈 값·잘못된 길이·허용되지 않은 문자·중복 room query는 코드 자동 입력을 하지 않고
온라인 화면에 오류 안내를 표시한다. 사용자는 코드를 직접 고쳐 참가할 수 있다.
없는 방, 정원 초과, 이미 진행 중인 방은 기존 서버 ack 오류를 그대로 표시한다.
클라이언트 검증은 서버 validation을 대체하지 않는다.

## 재접속 우선순위와 URL 정리

유효한 형태의 기존 sessionStorage reconnect session이 있으면 먼저 room:resume으로
복구한다. URL에 다른 방 코드가 있더라도 새 room:join을 보내지 않는다.
복구가 거부되면 기존 정책대로 세션을 지우고 이유를 표시한다. 이후 참가하려면
사용자가 닉네임과 참가 버튼으로 명시적으로 요청해야 한다.

서버 room:state로 입장/복구가 확인되면 history.replaceState로 room query만 제거한다.
다른 query·hash와 현재 경로는 보존하며 페이지를 재로드하지 않는다.
F5는 기존 토큰으로 원래 좌석을 복구한다. 재대결은 같은 방 안의 기존 흐름을 유지한다.
참가하지 않고 게임 선택으로 돌아가도 room query를 정리한다.

## 복사와 모바일

Clipboard API 성공·실패를 텍스트 status로 안내한다. API가 없거나 권한이 거부되어도
readonly **초대 링크** 입력란을 선택해 수동 복사할 수 있다. 입력란은 focus 시 전체 선택한다.
긴 URL은 입력란 안에서 표시되어 대기실 폭을 늘리지 않는다. 게임판 toolbar에는
새 초대 컨트롤을 추가하지 않았다. 별도 Router나 Web Share 의존성은 추가하지 않았다.

## 검증

`npm run test:online`에 파싱·정규화·링크 보안·URL 정리 unit 테스트가 포함된다.
`npm run test:e2e`는 2인/3인 독립 컨텍스트의 초대 참가, 복사 성공/권한 거부/API 없음,
닉네임 필수, 없는 방/정원 초과/진행 중 거부, 잘못된 URL, 대기실·게임 F5의 토큰 우선순위를
검증한다. 360/390px 프로젝트와 375/412px 추가 viewport에서 대기실 overflow도 확인한다.
